# HTTP server на C++

HTTP/1.1-сервер на C++20 поверх TCP. Использует сокеты и собственный HTTP-парсер. Каждое принятое соединение обслуживается отдельным потоком. Поддерживает GET-маршруты, проверку заголовков и текстовые ответы.

## Сборка и запуск

Текущая реализация рассчитана на **macOS**: используется опция сокета `SO_NOSIGPIPE`. Нужен компилятор с поддержкой C++20, включая `std::counting_semaphore`, и Command Line Tools.

Из корня проекта:

```sh
sh build.sh
./exec_server
```

Скрипт собирает `exec_server` и `exec_client`. Для HTTP-запросов используется **curl**. Сетевой код в `client.cpp` сейчас закомментирован; `exec_client` запросы не отправляет.

По умолчанию сервер слушает `127.0.0.1:12345`. Остановка — Ctrl+C в терминале сервера.

## Маршруты

| Запрос | Статус | Тело |
|---|---|---|
| `GET /` | 200 | `Hello, HTTP!` |
| `GET /health` | 200 | `My health is ok` |
| `GET /unknown` | 404 | `Not found` |
| `POST /health` без тела | 405 | `Method not allowed` |

Для известного пути разрешён только GET; ответ 405 содержит `Allow: GET`. Неизвестный путь возвращает 404 независимо от метода, если запрос прошёл предварительные проверки.

Query string отделяется по первому `?`: `/health?probe=1` выбирает маршрут `/health`. Параметры сохраняются строкой, но не разбираются на пары и не влияют на ответ.

Все ответы содержат `Content-Type: text/plain; charset=utf-8`, вычисленный в байтах `Content-Length` и `Connection: close`. Тела ответов не содержат дополнительного перевода строки в конце.

## Проверка через curl

Запусти команды в другом терминале. Опция `-i` показывает статус и заголовки вместе с телом.

```sh
curl --http1.1 -i --max-time 3 http://127.0.0.1:12345/
curl --http1.1 -i --max-time 3 http://127.0.0.1:12345/health
curl --http1.1 -i --max-time 3 'http://127.0.0.1:12345/health?probe=1'
curl --http1.1 -i --max-time 3 http://127.0.0.1:12345/unknown
curl --http1.1 -i --max-time 3 -X POST http://127.0.0.1:12345/health
```

Первые три запроса возвращают 200, четвёртый — 404, пятый — 405 с `Allow: GET`.

Примеры запросов, возвращающих 400:

```sh
# Отсутствующий Host
curl --http1.1 -i --max-time 3 -H 'Host:' http://127.0.0.1:12345/health

# Некорректная длина тела
curl --http1.1 -i --max-time 3 -H 'Content-Length: 5abc' http://127.0.0.1:12345/health

# Неподдерживаемое тело запроса
curl --http1.1 -i --max-time 3 --data 'hello' http://127.0.0.1:12345/health
```

Проверки формата и тела выполняются до маршрутизации, поэтому POST с ненулевым телом получает 400, а POST без тела на существующий маршрут — 405.

## Как устроен код

| Файл | Назначение |
|---|---|
| `server.cpp` | `accept()`, ограничение числа клиентов, запуск потоков, проверки запроса и отправка ответа |
| `utils.hpp` | `MySocket`: владение дескриптором, чтение порции байтов, полная отправка, таймауты и опции сокета |
| `connection.hpp` | `HttpConnection`: буфер входящих данных, чтение до конца заголовков, разбор первой строки и заголовков |
| `router.hpp` | Выбор статуса и тела по методу и пути, формирование ответов |
| `constants.hpp` | Адрес, порт, предел соединений и таймаут ввода-вывода |
| `logging.hpp` | Вывод логов с синхронизацией между потоками |
| `build.sh` | Сборка с C++20 и предупреждениями компилятора |

TCP передаёт поток байтов без границ HTTP-сообщений. `HttpConnection` накапливает порции из `recv()` до `\r\n\r\n`. Байты после разделителя сохраняются в буфере. Заголовки разбираются по первому двоеточию, их имена приводятся к нижнему регистру; пробелы и табуляция по краям значений удаляются. Повторяющиеся заголовки сохраняются.

## Текущее поведение и ограничения

- Одно соединение обслуживает один запрос и затем закрывается. Keep-alive пока не реализован.
- Принимается версия `HTTP/1.1`. Проверки парсера не покрывают полный стандарт HTTP.
- `Host` должен встречаться ровно один раз и иметь непустое значение. Полная проверка синтаксиса адреса пока отсутствует.
- `Content-Length` может отсутствовать или быть равен нулю. Пустые, нечисловые, переполненные и повторные значения отклоняются с 400.
- Ненулевое тело и любое присутствие `Transfer-Encoding` отклоняются с 400. Это ограничение проекта; сами по себе тела запросов допустимы в HTTP.
- Лимит заголовков — 16 KiB вместе с разделителем. При превышении лимита или ошибке чтения соединение закрывается без HTTP-ответа.
- До 64 одновременно обслуживаемых соединений. При исчерпании слотов новое соединение закрывается.
- Таймаут операций чтения и записи — 30 секунд; это таймаут операции, а не общий дедлайн запроса.
- HTTPS/TLS, chunked-кодирование и HTTP/2–HTTP/3 не реализованы.

## Наблюдение трафика

На macOS запросы к localhost можно увидеть через loopback-интерфейс `lo0`:

```sh
sudo tcpdump -i lo0 -nn -s 0 -A 'tcp port 12345'
```

Для записи захвата выполни команду, отправь несколько запросов curl и останови захват через Ctrl+C:

```sh
sudo tcpdump -i lo0 -nn -s 0 -w /tmp/http-server.pcap 'tcp port 12345'
```

Открой файл в Wireshark, установи фильтр `tcp.port == 12345` и выбери **Follow → TCP Stream**. Если порт не распознан как HTTP, используй **Decode As… → HTTP**.
